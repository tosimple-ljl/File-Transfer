课程作业：基于 Qt 的 Socket 文件传输工具
一、 作业目标
本实验要求综合利用本学期所学的 Qt 核心知识，实现一个基于 TCP Socket 的“文件传输工具”，能够在客户端与服务端之间可靠地传输文本文件与图片文件。通过本实验，学生应达到以下目标：

掌握 UI 设计与资源管理：熟练使用 Qt Designer（.ui 文件）进行界面布局，理解 UI 编译过程；掌握 Qt 资源系统（.qrc）和 QSS 样式表美化界面。

深化信号与槽机制：熟练运用信号与槽响应按钮、网络状态变化，并掌握跨窗口（设置对话框与主窗口）及控件间的通信。

掌握网络编程与事件驱动：深入理解 Qt 的事件机制与 QTcpSocket / QTcpServer 的异步通信模型，熟练运用虚函数重写（如拖拽事件、绘制事件）或事件过滤器实现自定义交互逻辑（如拖拽文件到窗口自动发送）。

培养工程查阅能力：养成在开发过程中主动查阅 Qt 官方帮助文档（Qt Assistant）和网络编程相关资料的习惯。

二、 功能需求
2.1 基础通信功能（必做）
服务端：能够监听指定端口（QTcpServer::listen），接受客户端连接（incomingConnection / newConnection），并持续接收数据。

客户端：能够连接到指定 IP 和端口（QTcpSocket::connectToHost），并向服务端发送数据。

文本文件传输：支持选择本地 .txt 等文本文件，将其内容完整发送给对端，接收方能够保存为同名文件，内容与原文件一致（无丢失、无乱码）。

图片文件传输：支持选择 .png / .jpg / .bmp 等图片文件，将其二进制数据完整发送，接收方能够还原为可正常打开显示的图片。

分包与粘包处理：必须自定义简单的协议头（如：消息类型 + 文件名长度 + 文件名 + 文件大小 + 文件数据），在接收端正确分包、组包，避免 TCP 粘包导致文件损坏。

显示与反馈：界面实时显示传输日志（连接状态、发送/接收进度、文件名、文件大小）；提供进度条（QProgressBar）展示传输进度。

错误处理：对连接失败、断开连接、文件打开失败、发送失败等情况，通过状态栏或 QMessageBox 给出提示，保证程序不崩溃。

2.2 输入 / 交互方式
鼠标拖拽文件输入（基于鼠标事件 / 拖拽事件重写）

通过重写拖拽相关事件，实现"把文件拖进窗口即发送/接收"的体验。

界面上提供一个"拖拽接收区"（如 QLabel 或自定义 QWidget）。

用户拖动文件进入该区域时，界面给出高亮/边框反馈；松开鼠标时，自动读取拖入的文件并将其发送（客户端）或保存（服务端）。

实现方式须体现虚函数重写（如 dragEnterEvent、dropEvent）或事件过滤器的正确使用。

2.3 界面与交互要求
布局管理器：使用布局管理器（Layouts）进行界面排版，禁止纯坐标硬编码，保证窗口缩放时控件自适应。

QSS 美化：使用 QSS 为按钮、进度条、日志区、拖拽接收区设置自定义样式（如悬停变色、圆角边框、拖拽高亮等）。

资源文件：将用到的图标（连接、发送、打开文件等）通过 Qt 资源系统（.qrc）引入项目。

窗口通信（必做项）：实现一个"连接设置"对话框（用于设置 IP 地址、端口、保存路径等）。要求通过信号与槽将对话框中的参数传递给主窗口，考察窗口间通信能力。

三、 技术要求与约束
开发环境：C++、Qt 6（Qt Creator），使用 QTcpSocket 与 QTcpServer（需在 .pro 中添加 network 模块）。

UI 文件：所有界面使用 .ui 文件设计。

架构分离：UI 显示（View）与网络通信逻辑（Model / 传输管理类）需适度分离，不建议将所有代码堆砌在 MainWindow 中（建议单独封装 FileSender / FileReceiver 类）。

事件处理：须在代码中体现虚函数重写或事件过滤器的正确使用（拖拽事件或鼠标事件均可）。

传输可靠性：要求处理"分次到达"的数据拼接，确保大文件也能完整接收；建议单次发送采用 write + bytesWritten 信号驱动的流水线方式，避免一次 write 过大内存。

四、 提交要求
提交完整的 Qt 项目文件夹（包含 .pro、.h、.cpp、.ui、.qrc 等），客户端与服务端可置于同一项目（或分两个子项目）。

确保项目可正常编译运行，代码需包含必要的中文注释（特别是信号与槽连接、Socket 读写、分包组包、事件处理函数部分）。
